# Constraints
Scope: current directory

- **Canonical per-home runtime isolation**: MCP runtime reuse must be keyed by a validated real JMeter-home path, serialize operations within one home, and keep different homes in isolated worker JVMs. Violation: JMeter static state or plugin classes can cross runtime boundaries, or equivalent homes can create duplicate workers.
- **No implicit replay after fatal runtime failure**: A crash, timeout, protocol failure, or failed initialization must fail the in-flight call and evict that runtime generation; only a later independent call may rebuild it. Violation: a mutating MCP request can execute more than once without caller authorization.
- **Request-scoped plans and target-bound legality**: Process-lived caching may retain only bounded, immutable, non-authorizing descriptive component metadata (including successful descriptor metadata) plus immutable runtime identity; target-bound row shape, legality, and property acceptance remain request-scoped and must never be cached or treated as authoritative. Mutable JMX plans must be loaded for each operation. Violation: an MCP call can observe stale or cross-request plan state or authorize a target/property from cached metadata.
- **Narrow GUI semantic reflection**: Private binding/table reflection is permitted only inside a verified JMeter 5.6.3 worker, under fixed traversal/candidate/result/time budgets, with immutable worker-lifetime success and negative caching. It must not add component/property allowlists, row-family mappings, GUI-completeness claims, reflection details in protocol output, or cached target authorization. Violation: MCP exposes or depends on reflection handles/classes, retries a failed observation in the same worker, or treats cached metadata as permission to mutate a target.
- **Windowless command acceptance**: MCP discovery and mutation may use bounded non-visible worker objects but must not open top-level windows, invoke desktop GUI/openability validation, execute samplers or loads, or start remote services. Violation: command success depends on a GUI lifecycle or load execution instead of graph and SaveService verification.
- **Trusted executable JMeter home**: `jmeter_home` remains an intentional per-call override, and the selected JMeter installation, properties, class paths, and plugins are trusted same-user executable code. Runtime isolation is not a privilege or filesystem sandbox. Violation: documentation or tool schemas imply that an untrusted JMeter-shaped directory is safe to select, or silently remove the per-call override.
- **Bounded MCP inputs**: Reject JSON-RPC lines above 8 MiB before JSON parsing and YAML patches above 4 MiB before command execution/full patch allocation; rejecting one oversized line must not end the stdio session. Violation: an MCP client can cause unbounded request/patch buffering or an oversized request starts a worker.
